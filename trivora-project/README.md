# Trivora Technologies

A responsive company website, Express API, and admin dashboard for project enquiries. The API stores enquiries in Supabase Postgres and can optionally send email notifications.

## Project layout

```text
trivora-project/
├── frontend/                 # Static website and admin dashboard
│   ├── index.html
│   ├── admin.html
│   ├── api-config.js         # Local API default; production config is generated by build.js
│   ├── build.js
│   └── assets/
├── backend/
│   ├── database/schema.sql   # Supabase/Postgres tables and starter services
│   └── src/
└── render.yaml               # Render web service blueprint
```

## Deploy the application

The GitHub repository contains this project under `trivora-project/`. Connect that repository to each provider and use the following project roots:

1. **Supabase:** Create a Postgres project. Copy its **Session pooler** connection string from **Connect** and URL-encode any special characters in the database password. Do not put the connection string in frontend files or commit it.
2. **Render:** Create a Blueprint from the repository root using `render.yaml`. Set `DATABASE_URL` to the Supabase session-pooler connection string when prompted. The blueprint generates a secure `JWT_SECRET`. After the first deploy, note the API URL (for example, `https://trivora-api.onrender.com`), then set `FRONTEND_ORIGIN` to the exact Vercel website origin. Multiple origins can be comma-separated.
3. **Vercel:** Import the same repository and set the project root to `trivora-project/frontend`. Before deploying, add the project environment variable `TRIVORA_API_BASE` with the Render URL followed by `/api` (for example, `https://trivora-api.onrender.com/api`). Vercel uses `vercel.json` and the build script to produce the static site. Once Vercel assigns the site's domain, set that exact `https://...vercel.app` origin as Render's `FRONTEND_ORIGIN` and redeploy/restart the API.
4. **Initialize the database:** From `trivora-project/backend`, set `DATABASE_URL` to the same Supabase connection string and run `npm ci` followed by `npm run db:init`. This creates the tables and starter service records. Then run `npm run admin:create` to securely create the first dashboard account.

Do not commit `.env` files, database credentials, admin passwords, or JWT secrets. Render's free web service may sleep when idle and take time to wake up.

### Local development

- Node.js 18 or newer
- A Supabase Postgres project (or another Postgres database with SSL enabled)

In `backend/`, copy `.env.example` to `.env`, set `DATABASE_URL` and a strong `JWT_SECRET`, then run:

```bash
npm ci
npm run db:init
npm run admin:create
npm run dev
```

The API listens on `http://localhost:5000`. Its health check is `http://localhost:5000/api/health`. Serve the `frontend/` directory with a local static server (for example, VS Code Live Server on port 5500); `api-config.js` points the website to the local API by default. Set `FRONTEND_ORIGIN` to the local site's exact origin in `backend/.env`.

To verify/build the static frontend locally, run `npm run build` from `frontend/`. The build output is written to `frontend/dist/`. For Vercel, `TRIVORA_API_BASE` must be set to the HTTPS Render API URL ending in `/api`.

## Admin dashboard

Visit `/admin.html` on the deployed website and sign in with the account created by `npm run admin:create`. The admin token is kept in `sessionStorage` for the current browser tab/session and expires according to `JWT_EXPIRES_IN`.

## API endpoints

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| GET | `/api/health` | Public | API and database health check |
| GET | `/api/services` | Public | Read active services from Postgres |
| POST | `/api/inquiries` | Public, rate-limited | Validate and store an enquiry |
| POST | `/api/auth/login` | Public, rate-limited | Admin login and JWT issue |
| GET | `/api/admin/inquiries` | Admin JWT | List up to 500 recent enquiries |
| PATCH | `/api/admin/inquiries/:id` | Admin JWT | Update an enquiry status |
| DELETE | `/api/admin/inquiries/:id` | Admin JWT | Delete an enquiry |

## Email notifications (optional)

To send an email notification when a new enquiry arrives, configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `NOTIFY_EMAIL`, and `FROM_EMAIL` in the Render environment. Enquiries are stored even when email is not configured or delivery fails.

## Production checklist

- Use HTTPS and allow only the exact Vercel origin in Render's `FRONTEND_ORIGIN`.
- Keep the Supabase connection string and `JWT_SECRET` in provider environment settings, never in frontend code.
- Create an admin account with a strong, unique password.
- Test contact submissions, admin sign-in, status updates, and deletion.
- Configure SMTP if email alerts are needed, and test delivery.
- Add a privacy policy and confirm enquiry retention practices fit applicable privacy law.
- The included portfolio visual is a concept illustration, not a claim that the pictured projects are completed client work.

Existing records in a separate MySQL database are not copied by `db:init`; export and migrate those separately if they need to be retained.
